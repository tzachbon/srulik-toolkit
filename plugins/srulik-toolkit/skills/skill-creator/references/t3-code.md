# T3 Code mapping

Use the provider's namespaced skill invocation and verify source identity.
T3's current thread can have an older installed plugin than the checkout; a
file path in a task does not change runtime installation or workspace binding.

Use native asynchronous question tools while work continues. Required answers
and implementation authority remain pending until actually received. A new
authoring request invokes `create-plan`; authorized execution invokes
`implement-plan` and consumes the references within its approved task.

Follow the current T3 orchestration instructions: discover capabilities with
`orchestrator_capabilities` before the first `delegate_task`; set model options
in `target.options`, and use `isolation: "worktree"` for separate writer
checkouts. Same-provider native children are appropriate when the active rules
allow them. Never create a top-level conversation as a substitute child.

Retain task IDs and obey each delegated task's `next`. If completion wakes the
parent, end the turn rather than polling. Use a new task for a new review
round, and cancel replaced tasks with `task_cancel`. Children do not inherit
publication or installation authority. Keep paired evaluation settings and
outputs explicit; serialize heavy runs when host capacity requires it.

Store only actual completion telemetry. A T3 receipt or native child result may
not contain the same timing/token fields as another transport; omit unavailable
measurements. A model's claim of success is not produced-artifact evidence.

For static HTML presentation use `html_preview` then `html_render` when those
tools are available under the active visual instructions. Pass the generated
file's HTML; never start a viewer server or claim an on-disk screenshot displays
the artifact. Otherwise return the supported clickable absolute file link and
state that in-app display is unverified. Import explicit completed feedback
through the host's supported file exchange; distinguish synthetic round trips
from actual human review.

This mapping documents tool contracts, not live verification of the user's
current conversation. Native CLI smoke results prove those exact isolated
runtimes, not automatic activation of a newly bundled skill here.
